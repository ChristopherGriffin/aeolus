# 0052. SNMP through net-snmp, set like any system setting

- Status: Accepted
- Date: 2026-10-03
- Proposed by: Griff: SNMP on the System tab, with v2c and v3, net-snmp, and anyone on the management network allowed to query; written up by Claude and accepted with the merge
- Refines: 0040, 0039, 0041, 0047, 0048, 0050

## Decision

- **SNMP is a group of system settings** (`system.snmp`, Locations tree), set on a folder or AP and inherited like the rest:
  - `enabled`; unset, the AP does not answer SNMP;
  - `community`: a read-only v2c community, sealed like a passphrase (0027);
  - `v3.user`, `v3.auth`, `v3.privacy`: a read-only v3 user, with an authentication passphrase used with SHA and a privacy passphrase used with AES, both sealed;
  - `location` and `contact`, as sysLocation and sysContact. sysName stays the AP's hostname.
- **v2c, v3 or both,** as set.
  - All access is read-only. No setting gives write access.
  - The schema keeps spaces, quotes and control characters out of these values, because snmpd's config takes them on lines of their own.
- **SNMP is reachable from the management network.** snmpd listens on all of the AP's addresses, and the only one an AP has is its management address: its Wi-Fi VLANs are bridged without one. There is no source list.
- **The agent's installer adds net-snmp's SSL build** (`snmpd-ssl`), which v3's AES needs.
  - snmpd starts when it is installed, answering OpenWrt's default communities: `public`, and `private` from the AP itself. So the installer turns it off and deletes those at once.
  - As with usteer (0050), the agent itself never installs packages.
- **Aeolus owns all of snmpd's config:**
  - While SNMP is off, the config is only that it is off, so no default community is left behind.
  - While it is on, the config is exactly the intent's community, for IPv4 and IPv6, and the intent's v3 user, both read-only. snmpd's engine ID comes from the uplink port's address, so it stays the same across reboots.
- **The checks:**
  - **Config check (0029):** SNMP turned on with no community and no v3 user is held. So is a v3 user without both passphrases. The preview shows this.
  - **Render check (0039)** holds snmpd's config to the intent:
    - enabled or not;
    - the communities, and no others;
    - no write access;
    - the v3 user with SHA and AES;
    - the location and contact.
  - **Never quoted:** the render check never quotes a secret, and the manager's kept copy of the rendered UCI blanks snmpd's secrets (0041).
  - **Missing snmpd:** a config asking for SNMP on an AP without snmpd is refused, and the AP keeps what it runs.
- **The System tab has an editor for every system setting,** built from the schema like the network form (0048), in one change with a preview and a reason:
  - its sections are Place and time, Logging, SNMP and Agent, with management addressing folded under Management and more;
  - SNMP's fields show once SNMP is turned on;
  - the preview warns when a change restarts the Wi-Fi (the country) or reloads the AP's network (management).
  - List settings, such as NTP servers and SSH keys, are edited one per line.

## Consequences

- **Installing the agent now adds about 5 MB,** for net-snmp and OpenSSL. An AP with little flash may not have room. The installer says so, and SNMP is then refused on that AP until snmpd is installed.
- **A sysupgrade drops snmpd,** as it does usteer. SNMP is refused on that AP until it is installed again.
- **APs installed before this need snmpd installed by hand,** turned off the same way, plus the new agent.
- **Traps, and SNMP write access, are left out.** Each would be a later decision.
